# Implementation Blueprint: Zalo Smart Todo Offline LLM Lab (Google Colab Sync)

**Target System:** Phase 2 Hybrid Router (`technical_specification_phase_2_3.md`) — Offline Model Evaluation, QLoRA Fine-Tuning & Quantized GGUF Export Pipeline.  
**Execution Model:** Local CPU Development & Unit Testing $\rightarrow$ Git Sync $\rightarrow$ Google Colab (`NVIDIA T4 15GB VRAM`) Zero-Shot Benchmark, Training & Export $\rightarrow$ Google Drive Persistence $\rightarrow$ Local Ollama / `llama-server` Deployment.


## 1. Sync Architecture & Repository Structure

The repository is designed so all business rules, prompt formatting, dataset validation, and unit tests run **locally on CPU without a GPU**. Google Colab acts purely as a stateless GPU runner that clones/pulls from GitHub and saves heavy artifacts (LoRA adapters, merged weights, GGUF files, benchmark reports) to Google Drive.

## 2. Phase 1: 1:1 Parity with Phase 2 Router Spec (`src/spec/`)

Every prompt and validation check in this lab must mirror the Node.js production router in `technical_specification_phase_2_3.md` so offline metrics directly predict production accuracy.

### 2.1. Tool Schemas & Dynamic Anti-Injection Scoping (`src/spec/tools_schema.py`)
Define the exact 5 tools and parameter constraints from §10:
1. `draft_task`: `title` (1–120 chars), `group` (`work` | `health` | `family`), `due_date` (optional `YYYY-MM-DD`), `due_time` (optional `HH:mm`), `assignee` (`self` | `other` | `unassigned`), `importance` (`high` | `normal` | `low`), `note` (optional, max 300 chars), `intent` (`merge` | `replace`).
2. `draft_meeting`: `title` (1–120 chars), `group` (`work` | `health` | `family`), `start_date` (optional `YYYY-MM-DD`), `start_time` (optional `HH:mm`), `duration_minutes` (`30` | `60` | `120`), `location` (optional, max 80 chars), `note` (optional, max 300 chars), `intent` (`merge` | `replace`).
3. `propose_update`: `item_code` (key in current snapshot, e.g., `T1`, `M1`), `action` (`mark_done` | `postpone_task` | `reassign_task` | `complete_meeting` | `cancel_meeting` | `reschedule_meeting`), `new_date` (optional `YYYY-MM-DD`), `new_time` (optional `HH:mm`), `new_assignee` (optional `self` | `other` | `unassigned`).
4. `query_schedule`: `target` (`all` | `tasks` | `meetings` | `overdue`), `start_date` (optional `YYYY-MM-DD`), `end_date` (optional `YYYY-MM-DD`), `assignee_filter` (`all` | `self` | `other`).
5. `clarify_ambiguity`: `question_text` (required, max 2 short Vietnamese sentences).

**Security Boundary (`get_scoped_tools(combined_text)`):**
- If `len(combined_text) > 220` OR `combined_text.count("\n") >= 4` OR any lowercase marker in `["kính gửi", "thông báo", "công văn", "giấy mời", "chuyển tiếp", "v/v:"]` appears in `combined_text`, return **only** `[draft_task, draft_meeting, clarify_ambiguity]` (even when a draft is already open).
- Otherwise, return all 5 tools.

### 2.2. KV-Cache-Optimized Prompt Builder (`src/spec/prompt_builder.py`)
Structure the System Prompt so **static rules come first** (maximizing prefix KV-cache reuse in Ollama / `llama.cpp` during local inference) and **per-request dynamic context comes last**:

1. **Static Block (Top of System Prompt):**
   - Role definition (`Bộ Điều Phối Lịch & Công Việc Nội Bộ` serving `Lãnh đạo` and `Trợ lý`).
   - Task-vs-Meeting decision rules (§10):
     - Meeting when text has a clock time or part of day AND a place or one of `họp`, `gặp`, `khám`, `mời` (e.g., `"Nhắc anh 8h sáng thứ 7 đi khám ở BV"` $\rightarrow$ `draft_meeting`).
     - Task when work is due by a deadline (`chuẩn bị`, `nộp`, `soạn`, `gọi`, `nhắc` someone to do something) without a meeting place.
     - Conflicting signals or missing day $\rightarrow$ `clarify_ambiguity` (or omit `due_date`/`start_date` in `draft_*`).
   - Vietnamese Time Table (§10):
     - `Đầu giờ sáng` = `08:00` | `Sáng` = `08:30` | `Trưa`, `cuối giờ sáng`, `trước chiều` = `11:30`
     - `Đầu giờ chiều` = `13:30` | `Chiều` = `15:00` | `Cuối giờ chiều`, `tan tầm` = `17:00` | `Tối` = `19:30`
     - Spoken hours `1..6` without part of day default to afternoon (`13:00–18:00`, e.g., `"2 rưỡi"` = `14:30`); with `sáng` stay morning (`02:00`). Hours `7..11` without part of day are morning; `12`/`12h` = `12:00`.
   - Role-Aware Assignee Table (§11):
     - Actor `Lãnh đạo`: `tôi, anh, mình, nhắc anh` $\rightarrow$ `self`; `em, trợ lý, nhờ em` or subjectless imperative $\rightarrow$ `other`.
     - Actor `Trợ lý`: `em, mình, tôi` $\rightarrow$ `self`; `sếp, anh, lãnh đạo, lịch của anh` $\rightarrow$ `other`.
   - Multi-Turn `clarify` Merge Rule (§11 + polish):
     ```text
     Khi hàng rào dữ liệu có bản clarify đang mở (source_text và partial):
     - Gộp <user_message> mới với source_text và partial.
     - Giữ nguyên tool_name, item_code và action đã có trong partial.
     - Điền các đối số còn thiếu từ câu mới.
     - Gọi đúng tool đó. Không gọi tool khác và không hỏi lại điều đã có trong partial.
     - Nếu partial là null, hãy chọn tool tạo mới hoặc cập nhật phù hợp sau khi đã gộp đủ thông tin.
     ```
2. **Dynamic Nonce-Fenced Block (Bottom of System Prompt + User Turn):**
   - Generate a per-request random nonce (e.g., `FENCE_9a8b7c6d`), strip it from untrusted inputs, and wrap:
     - Actor role & current `Asia/Ho_Chi_Minh` (`+07:00`) timestamp.
     - Pre-computed calendar covering Monday of current week through `today + 13 days`, labeling past days `(đã qua)`, `(Hôm nay)`, `(Ngày mai)`, `(Mốt / Ngày kia)`, `Tuần này`, `Tuần sau`, `Đầu tuần sau`, and Sunday-safe `Cuối tuần này` (where on Sunday, Saturday is yesterday and Sunday is today).
     - Formatted open items (`[T1] Việc | ...`, `[M1] Họp | ...`).
     - Active `confirm_draft` or `clarify` JSON payload (if any).
   - Wrap `<user_message>` in a second nonce fence with explicit anti-injection instructions.

### 2.3. Output Validator (`src/spec/validator.py`)
Validate every parsed model tool call against:
- Allowed tool list from `get_scoped_tools()`.
- Strict date (`YYYY-MM-DD`, real calendar date) and time (`HH:mm`, `00:00`–`23:59`) formats. Reject any timestamp containing `Z` or non-`+07:00` offsets.
- `item_code` membership in the sample's `snapshot` dictionary.
- Valid enum values for `group`, `assignee`, `importance`, `duration_minutes` (`30`, `60`, `120`), `action`, and `target`.

## 3. Phase 2: Model Registry & Pluggable Adapters (`configs/models.yaml`, `src/adapters/`)

### 3.1. Model Lineup (`configs/models.yaml`)
Support benchmarking and training across both **Qwen** and **Gemma** families within Colab's 15GB T4 VRAM limit:

| Model Key | HuggingFace / Unsloth Repo ID | Adapter | Approx. 4-bit VRAM | Notes |
| :--- | :--- | :--- | :--- | :--- |
| `qwen2.5-7b` | `unsloth/Qwen2.5-7B-Instruct-bnb-4bit` | `qwen` | ~5.5 GB | Fast baseline; native Hermes tool calling; no thinking overhead. |
| `qwen2.5-14b` | `unsloth/Qwen2.5-14B-Instruct-bnb-4bit` | `qwen` | ~9.5 GB | Highest Vietnamese & reasoning accuracy; fits T4 15GB with `max_seq_length=3072`. |
| `qwen3-8b` | `unsloth/Qwen3-8B-unsloth-bnb-4bit` | `qwen` | ~6.0 GB | Must pass `enable_thinking=False` to prevent `<think>` latency blowup. |
| `gemma2-9b` | `unsloth/gemma-2-9b-it-bnb-4bit` | `gemma` | ~6.5 GB | Strong Vietnamese instruction following; uses JSON tool wrapper. |
| `gemma3-12b` | `unsloth/gemma-3-12b-it-unsloth-bnb-4bit` | `gemma` | ~8.5 GB | Newer multimodal/text architecture; strong structured JSON accuracy. |

### 3.2. Adapter Implementations (`src/adapters/`)
- **`QwenAdapter` (`qwen_adapter.py`):**
  - Uses `tokenizer.apply_chat_template(messages, tools=scoped_tools, tokenize=False, add_generation_prompt=True, enable_thinking=False)`.
  - Parses `<tool_call>{"name": ..., "arguments": ...}</tool_call>` blocks (with fallback JSON extraction if raw JSON is emitted).
- **`GemmaAdapter` (`gemma_adapter.py`):**
  - Injects a compact, deterministic JSON-only tool calling specification (listing the scoped tool schemas and requiring a single JSON object `{"name": "<tool_name>", "arguments": {...}}`) into the user/system prompt since Gemma templates do not use Hermes `<tool_call>` tags.
  - Parses fenced ` ```json ... ``` ` or raw JSON objects and validates against `src/spec/validator.py`.

## 4. Phase 3: Zero-Shot Evaluation & Golden Dataset (`data/golden_eval.jsonl`, `src/eval/`)

### 4.1. Golden Evaluation Dataset (`data/golden_eval.jsonl`)
Each line is a self-contained JSON test record:
```json
{
  "id": "EVAL-004",
  "category": "time_and_assignee",
  "clock_iso": "2026-11-13T16:10:00+07:00",
  "actor": "leader",
  "user_text": "Giao em chuẩn bị hồ sơ thầu trước chiều thứ 2 tuần tới, việc gấp nhé",
  "open_tasks": [],
  "open_meetings": [],
  "snapshot": {},
  "dialog_state": null,
  "expected_tool": "draft_task",
  "expected_args": {
    "group": "work",
    "due_date": "2026-11-16",
    "due_time": "11:30",
    "assignee": "other",
    "importance": "high"
  },
  "title_must_contain": ["hồ sơ thầu"]
}
```
Include **at least 80 cases** covering:
1. All LLM scenarios from §14 (Cases 3–12, 17, 18, 22, 23).
2. Vietnamese time nuances (`trước chiều`, `đầu giờ sáng`, `cuối giờ chiều`, `tan tầm`, `2 rưỡi`, `2h sáng`, `12h`).
3. Sunday boundary dates (`clock_iso = 2026-11-15T09:00:00+07:00`) verifying `cuối tuần này` vs `thứ 2 tuần tới`.
4. Role-flipped pronouns (`Leader` vs `Assistant` using `anh`, `em`, `sếp`, `mình`).
5. `confirm_draft` follow-up edits (`intent: "merge"` vs `"replace"`).
6. Multi-turn `clarify` follow-ups (both with populated `partial` and with `partial: null`).
7. Long forwarded official documents (`>220` chars, `công văn`, `giấy mời`) with embedded prompt injection attacks.

### 4.2. Benchmark Runner (`src/eval/run_eval.py`)
- Evaluates one or more models (`--models qwen2.5-7b qwen3-8b gemma2-9b gemma3-12b qwen2.5-14b`) or a fine-tuned LoRA checkpoint (`--lora-path ...`).
- Enforces `max_seq_length = 3072`, `temperature = 0.0`, `max_new_tokens = 384`.
- Frees VRAM cleanly (`del model, tokenizer; gc.collect(); torch.cuda.empty_cache()`) between models so all 5 models can be benchmarked sequentially in a single Colab session without OOM.
- Outputs `results/benchmark_report.md` comparing:
  - **JSON & Schema Validity (%)**
  - **Tool Selection Accuracy (%)**
  - **Critical Argument Exact Match (%)**
  - **Prompt Injection Defense Rate (%)**
  - **p50 / p95 Inference Latency (s)** & **Peak VRAM (GB)**

## 5. Phase 4: Synthetic Dataset Generation (`src/dataset/synthesize.py`)

When zero-shot accuracy needs improvement (or to distill `qwen2.5-14b` / `gemini-2.5-flash` performance into a faster 7B–8B model for basic local hardware):
1. Generate **500 diverse Vietnamese scenarios** programmatically varying:
   - Reference dates across all 7 days of the week (including Sunday edge cases).
   - Actor roles (`Lãnh đạo` / `Trợ lý`).
   - Realistic Vietnamese office & military/administrative shorthand (`BTL TP`, `UBND`, `CV`, `TB`, `GM`, `BV ĐHYD`) and `\n---\n` multi-message debounced inputs.
   - Balanced distribution across `draft_task` (30%), `draft_meeting` (25%), `propose_update` (20%), `query_schedule` (10%), `clarify_ambiguity` (10%), and forwarded anti-injection letters (5%).
2. Query `gemini-2.5-flash` (`temperature=0.2` for phrasing diversity, `mode="ANY"`).
3. Run every output through `src/spec/validator.py` and deterministic rule assertions; automatically discard any invalid sample and write clean 90/10 splits to `data/train_valid.jsonl` and `data/val_valid.jsonl`.

## 6. Phase 5: QLoRA Fine-Tuning & Quantized GGUF Export (`src/train/`, `src/export/`)

### 6.1. T4-Safe QLoRA Training (`src/train/train_unsloth.py`)
Configure `configs/train_qlora.yaml` to run comfortably within 15GB VRAM:
- `max_seq_length: 3072`
- `load_in_4bit: true`
- `lora_r: 16`, `lora_alpha: 32`, `lora_dropout: 0`
- `target_modules: ["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]`
- `use_gradient_checkpointing: "unsloth"`
- `per_device_train_batch_size: 1`, `gradient_accumulation_steps: 8` (effective batch size = 8)
- `num_train_epochs: 3`, `learning_rate: 2e-4`, `lr_scheduler_type: "cosine"`, `warmup_ratio: 0.05`
- `optim: "adamw_8bit"`
- **Loss Masking:** Apply Unsloth's `train_on_responses_only` so loss is computed exclusively on the assistant's tool call tokens, preventing overfitting on the static system prompt.

### 6.2. Quantized Export & Local Hardware Optimization (`src/export/export_gguf.py`)
Export the fine-tuned model into two GGUF quantization tiers to Google Drive (`/content/drive/MyDrive/zalo-todo-models/<run_name>/`):
1. **`Q4_K_M`** (~4.7 GB for 7B–8B, ~9.0 GB for 14B): Best balance of speed and tool-calling precision.
2. **`IQ4_XS`** (~4.2 GB for 7B–8B, ~7.8 GB for 14B): Importance-matrix quantization that saves an extra ~10% VRAM, allowing a 12B–14B model to fit inside an 8GB VRAM GPU with minimal RAM offloading.
3. **Auto-Generated Ollama `Modelfile`:**
   ```dockerfile
   FROM ./model-Q4_K_M.gguf
   PARAMETER num_ctx 4096
   PARAMETER temperature 0
   PARAMETER top_p 1
   ```
   Include a `README_LOCAL_DEPLOY.md` in the export folder documenting how to start Ollama with `OLLAMA_FLASH_ATTENTION=1` and `OLLAMA_KV_CACHE_TYPE=q8_0` (halving KV-cache VRAM) and connect it to the Node.js backend via `LLM_PROVIDER=local`.

## 7. Phase 6: Google Colab Orchestrator (`notebooks/colab_runner.ipynb`)

Create a clean, well-documented 6-cell Jupyter notebook ready for Google Colab:
- **Cell 1 — Environment & Sync Setup:** Verify T4 GPU (`!nvidia-smi`), mount Google Drive (`/content/drive`), clone/pull the Git repository, and install `requirements-colab.txt`.
- **Cell 2 — Zero-Shot Multi-Model Benchmark:** Run `python -m src.eval.run_eval --models qwen2.5-7b qwen3-8b gemma2-9b gemma3-12b qwen2.5-14b` and display `results/benchmark_report.md`.
- **Cell 3 — Synthetic Dataset Generation (Optional):** Load `GEMINI_API_KEY` from Colab Secrets (`google.colab.userdata`) and run `python -m src.dataset.synthesize --count 500` if expanding the training set.
- **Cell 4 — QLoRA Fine-Tuning:** Run `python -m src.train.train_unsloth --config configs/train_qlora.yaml --model qwen2.5-7b` (or `qwen2.5-14b`).
- **Cell 5 — Post-Train Evaluation & GGUF Export:** Re-run `src.eval.run_eval` on the fine-tuned LoRA adapter to verify accuracy gains over zero-shot, then export `Q4_K_M` + `IQ4_XS` GGUF and `Modelfile` to Google Drive.
- **Cell 6 — Live Tunnel Smoke Test (Optional):** Install Ollama + `cloudflared`, load the exported GGUF model, and print a temporary HTTPS URL so the local Node.js Phase 2 router can run live end-to-end tests against the Colab GPU.

## 8. Acceptance Criteria & Definition of Done

Before concluding implementation, the AI Coding Agent must verify:
1. All files in `zalo-todo-llm-lab/` are created with clean modular separation and strict `pydantic` v2 schemas.
2. `pytest tests/test_spec_parity.py` passes 100% locally on CPU, verifying:
   - Calendar generation (including Sunday `this_saturday` / `this_sunday` behavior).
   - Dynamic tool scoping stripping `propose_update` and `query_schedule` on forwarded/long text.
   - Time normalization (`trước chiều` $\rightarrow$ `11:30`, `2 rưỡi` $\rightarrow$ `14:30`).
   - Validator rejection of `Z` timestamps and unknown `item_code` values.
   - `QwenAdapter` and `GemmaAdapter` prompt formatting and tool-call parsing round-trips.
3. Zero API keys, tokens, or sensitive sample data are hardcoded anywhere in the repository.
